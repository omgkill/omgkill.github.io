Redis Hash + ZSet 双结构设计模式

概述

在需要同时满足以下诉求的场景中，单一 Redis 数据结构往往力不从心：

  • 按某个维度排序展示列表
  • 支持分页查询
  • 支持按 ID 精确查询/删除单条数据
  • 数据过期自动淘汰
  • 计数统计

Hash + ZSet 双结构是解决这类问题的经典模式。

数据结构分工

1data:{bizKey}  →  Hash
2    field: itemID
3    value: json(ItemData)
4
5list:{bizKey}  →  ZSet
6    member: itemID
7    score:  sortValue（通常是时间戳）
结构职责
ZSet排序、分页、计数、范围过滤
Hash按 ID O(1) 精确查询/删除完整数据

两者通过 itemID 关联，ZSet 是索引，Hash 是数据存储。

Redis Cluster 下的 key 设计

Redis Cluster 中，Lua 脚本要求所有操作的 key 必须落在同一个节点，否则报 CROSSSLOT 错误。

通过 {} tag 强制两个 key 落在同一个 slot：

1data:{bizKey}   // slot 由 {bizKey} 决定
2list:{bizKey}   // slot 由 {bizKey} 决定，与上面相同

⚠️ 注意：{} tag 会导致同一个 bizKey 的所有数据集中在单个节点，如果 bizKey 基数很小（比如全局唯一的榜单），会造成热点问题。bizKey 基数足够大时（比如每个用户一个 key）则没有此问题。

核心问题：两个 key 的一致性

Lua 脚本在正常运行时是原子的，但 Redis 宕机时可能出现脚本部分执行，导致两个 key 数据不一致。

不一致有两种方向：

状态ZSetHash危害
方向A✅ 有❌ 无查询返回空，用户看不到数据
方向B❌ 无✅ 有数据永久丢失/泄漏，无任何入口能发现

方向A 可以自愈，方向B 不可自愈。

因此设计原则是：通过操作顺序，把所有异常收敛到方向A。

操作顺序设计

写入：先写 ZSet（索引），再写 Hash（数据）

1a('ZADD', listKey, score, itemID)   -- 第一步：建索引
2a('HSET', dataKey, itemID, val)     -- 第二步：存数据

崩溃场景分析：

1第一步后崩溃 → ZSet 有，Hash 无 → 方向A，可自愈 ✅
2第二步后崩溃 → ZSet 有，Hash 有 → 正常完成 ✅

删除：先删 Hash（数据），再删 ZSet（索引）

1a('HDEL', dataKey, itemID)   -- 第一步：删数据
2a('ZREM', listKey, itemID)   -- 第二步：删索引

崩溃场景分析：

1第一步后崩溃 → Hash 无，ZSet 有残留 → 方向A，可自愈 ✅
2第二步后崩溃 → Hash 无，ZSet 无    → 正常完成 ✅

自愈机制

所有异常都收敛到同一种状态：ZSet 有 member，但 Hash 中查不到对应数据（孤儿 member）。

在列表查询的 Lua 脚本中内置自愈逻辑，读时顺带清理：

 1local vals = a('HMGET', dataKey, unpack(ids))
 2local res = {}
 3local orphanIds = {}
 4for i = 1, #vals do
 5  if vals[i] then
 6    table.insert(res, vals[i])           -- 正常数据，收集返回
 7  else
 8    table.insert(orphanIds, ids[i])      -- 孤儿 member，记录
 9  end
10end
11if #orphanIds > 0 then
12  a('ZREM', listKey, unpack(orphanIds))  -- 原子清理
13end
14return res

自愈特点：

  • 触发时机：正常读请求顺带完成，无需定时任务或补偿逻辑
  • 正常情况下 orphanIds 永远为空，对性能零影响
  • 整个操作在同一个 Lua 脚本内，保持原子性

其他注意事项

Trim 用单 Lua 脚本，避免 TOCTOU 竞态

超出上限时裁剪旧数据，错误做法：

1// ❌ 两次独立操作，中间可能有其他请求插入新数据
2total := Count()
3delCount := total - maxCount
4Trim(delCount)

正确做法：把 ZCARD 和删除逻辑合并进同一个 Lua 脚本原子执行：

1local total = a('ZCARD', listKey)
2local delCount = total - maxCount
3if delCount <= 0 then return 0 end
4local ids = a('ZRANGE', listKey, 0, delCount - 1)
5a('ZREM', listKey, unpack(ids))
6a('HDEL', dataKey, unpack(ids))

Count 与 List 的统计口径要一致

如果 ListValid 用 +inf 作为上界：

1ZREVRANGEBYSCORE listKey '+inf' minScore

那么 CountValid 也必须用 +inf：

1ZCOUNT listKey minScore '+inf'  -- ✅
2ZCOUNT listKey minScore now     -- ❌ 口径不一致，导致分页计数偏小

适用场景

场景bizKeysortValue
用户邮件箱openID创建时间
用户消息通知openID创建时间
排行榜明细rankID分数
用户任务列表openID优先级

设计决策速查

决策原因
Hash + ZSet 双结构ZSet 排序/分页，Hash O(1) 按 ID 操作
{} tag 同节点Lua 脚本跨 key 操作要求同 slot
先写 ZSet 再写 Hash异常收敛到可自愈方向
先删 Hash 再删 ZSet异常收敛到可自愈方向
List 查询内置孤儿清理读时顺带自愈，无需额外补偿
Trim 单 Lua 脚本避免 TOCTOU 竞态
Count 与 List 上界一致保证分页计数准确
