GitHub Actions + Hugo + GitHub Pages 使用与踩坑总结

本文是一次完整实战后的复盘文档，记录了从 Hugo 构建、GitHub Actions 自动部署，到 GitHub Pages 发布过程中 真实遇到的问题、根因分析以及最终解决方案。

适用人群：

  • 使用 Hugo 写博客 / 文档
  • 使用 GitHub Actions 自动化部署
  • 部署目标为 GitHub Pages（同仓库 / 用户主页仓库）
  • 中文 + 技术博客为主

一、整体架构说明（先把事说明白）–

当前采用的架构

1Hugo 源码（main 分支）
2        ↓
3GitHub Actions
4        ↓
5hugo build（生成 public/）
6        ↓
7peaceiris/actions-gh-pages
8        ↓
9GitHub Pages（gh-pages 分支 或 Pages repo）

这是 GitHub 官方 + Hugo 社区最主流、最稳妥 的方案之一。

二、问题 1：GitHub Actions push 403（最致命问题）

❌ 报错信息

1Permission to omgkill/omgkill.github.io.git denied to github-actions[bot]
2fatal: unable to access 'https://github.com/...': 403

❌ 错误配置（真实踩坑）

1with:
2  publish_dir: ./public
3  personal_token: ${{ secrets.GITHUB_TOKEN }}

❌ 错误原因（根因）

  • GITHUB_TOKEN 不是 Personal Access Token（PAT）
  • peaceiris/actions-gh-pages 严格区分 token 类型
  • 把 GITHUB_TOKEN 填到 personal_token 参数 → 认证方式不匹配 → 403

✅ 正确做法（同仓库部署）

1permissions:
2  contents: write
3
4- name: Deploy
5  uses: peaceiris/actions-gh-pages@v3
6  with:
7    github_token: ${{ secrets.GITHUB_TOKEN }}
8    publish_dir: ./public

✅ 关键结论

场景正确 token 参数
同仓库 gh-pagesgithub_token
跨仓库 / *.github.iopersonal_token（PAT）

三、问题 2：为什么 GITHUB_TOKEN “默认有” 但还要写？

常见误解

既然 GitHub 默认提供 GITHUB_TOKEN，为什么还要写？

正确理解

  • GitHub 只负责生成 token
  • 不会自动注入到第三方 action 的参数中
  • action 是黑盒，必须显式传参
1with:
2  github_token: ${{ secrets.GITHUB_TOKEN }}

❗ 不写 ≠ 自动生效

四、问题 3：Hugo 生成链接指向 localhost

❌ 现象

  • 页面跳转到 http://localhost
  • CSS / JS / canonical / RSS 地址异常

❌ 原因

Hugo 在 build 阶段 使用 baseURL， 未指定时使用默认值（常见为 localhost）。

GitHub Pages 不会二次 rewrite HTML。

✅ 解决方案一（推荐）：写入 config.toml

1baseURL = "https://omgkill.github.io/"

✅ 解决方案二（CI 覆盖）

1hugo --baseURL https://omgkill.github.io/

⚠️ 重要细节

  • baseURL 必须以 / 结尾

五、问题 4：hugo –minify / –gc / –cleanDestinationDir 是什么

推荐的生产构建命令

1hugo --minify --gc --cleanDestinationDir

各参数含义

参数作用
–minify压缩 HTML / CSS / JS
–gc清理 Hugo asset cache
–cleanDestinationDir构建前清空 public/

✔ 安全 ✔ 不影响内容 ✔ 非激进优化

六、问题 5：GitHub Pages 是否需要域名

结论

  • 不必须
  • GitHub Pages 自带域名即可：
1https://omgkill.github.io

自定义域名时要做的额外配置

  1. DNS 指向 GitHub Pages
  2. Pages 设置里填写域名
  3. Deploy action 中保留 CNAME
1with:
2  cname: docs.example.com

否则每次 deploy 会覆盖 CNAME。

七、问题 6：中文 + 技术博客的 Hugo 配置要点

推荐语言策略

 1defaultContentLanguage = "zh-cn"
 2defaultContentLanguageInSubdir = false
 3
 4[languages.zh-cn]
 5languageCode = "zh-CN"
 6weight = 1
 7
 8[languages.en]
 9languageCode = "en"
10weight = 2

原因

  • 中国大陆用户
  • 中文为主、英文为辅
  • 更自然的 URL 结构
  • SEO 更合理

八、最终推荐的最小可跑 Workflow 模板

 1name: Deploy Hugo
 2
 3on:
 4  push:
 5    branches: [main]
 6
 7permissions:
 8  contents: write
 9
10jobs:
11  deploy:
12    runs-on: ubuntu-latest
13    steps:
14      - uses: actions/checkout@v4
15
16      - name: Build Hugo
17        run: hugo --minify --gc --cleanDestinationDir
18
19      - name: Deploy to Pages
20        uses: peaceiris/actions-gh-pages@v3
21        with:
22          github_token: ${{ secrets.GITHUB_TOKEN }}
23          publish_dir: ./public

九、经验总结（最重要）

  1. 403 ≠ GitHub 坏了，99% 是权限或 token 用错
  2. GITHUB_TOKEN ≠ PAT，用途完全不同
  3. Hugo 的 baseURL 是构建期核心参数
  4. 同仓库部署优先使用 github_token
  5. 不要过早折腾域名，先把内容跑稳
  6. 自动化的目标是：三年后还能一键 deploy

十、适合长期维护的心法

博客系统不是一次性工程， 而是一个 低维护、可复用、可迁移的资产。

这套方案的价值在于：

  • 不依赖个人电脑
  • 不依赖云服务器
  • 不锁死平台

你随时可以迁移、重建、复用。
